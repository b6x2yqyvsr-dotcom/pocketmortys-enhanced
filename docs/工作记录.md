## 1. 定位到的 4 个真 BUG

### BUG 1：`network_security_config.xml` 是纯文本，塞进去必崩

`file` 一眼就看得出来：`<?xml version="1.0" encoding="utf-8"?>` 明文开头。
APK 里这个文件必须是 **AXML 二进制格式**，否则：

    Resources$NotFoundException: File res/xml/network_security_config.xml
      from xml type xml resource
    Caused by: java.io.FileNotFoundException: Corrupt XML binary file

**证据**：把它 `repack` 进原版 APK 后 `aapt2 dump xmltree` 报
`Bad XML block: header size 28024 or total size 1702240364 is larger than data size 798`。

**修法**：不预置文件，构建时用 `aapt2 compile` + `aapt2 link` 现场编译，
再用 `aapt2 dump xmltree` 反解校验 `base-config` 与 `cleartextTrafficPermitted=true` 都在。

### BUG 2：`insecureHttpOption` 被改回 0

`assets/bin/Data/globalgamemanagers` 偏移 `209724` 处一个字节：`0` = NotAllowed，
`2` = AlwaysAllowed。`0` 时 Unity 在**发出请求之前**就拒掉明文 HTTP，
表现是服务端一条请求都收不到。

**证据**：`cmp -l` 原版 vs `明文本` 版，只有这一个字节不同（`209725: 0 → 2`，1-based）。

**修法**：构建时显式写 `2`，复验时读回来断言。

### BUG 3：`manifest.json` / `text.assetbundle` 被静默跳过

原始 APK 里**已经存在** `assets/AssetBundles/Android/manifest.json`（官方那份只有
72 字节、`{"text":{...},"version":"1"}`）。打包脚本把它当「条目已存在，跳过」，
于是塞进去的还是官方空清单。

**证据**：修好前复验输出 `manifest version=1 条目=1`；
客户端读到的 `loadedManifestVersion` 也是 1，随即报「过期资源」。

**修法**：新增条目若与基准 APK 同名，**先转成替换**再打包；复验时把清单
解析出来，断言 `条目 >= 150` 且与种子清单版本一致。

### BUG 4：两个「额外补丁」根本没进过任何产物

`OneTrust`（`0x1490980`）与 `MP暂停`（`0x15cc980`）在文档里写着，但
`patch_official_client.py` 的补丁表里**没有这两条**。

**证据**：对比 4 份 libil2cpp.so 的补丁点字节，`1-成品` 只有 8 处、`integrated` 只有 2 处。

**修法**：补进补丁表（共 10 处），并用「官方原版 + 10 补丁 == 1-成品 + 2 补丁」
做对拍，确认差异恰好只有那 8 个字节。

## 2. 最关键的一条：为什么「放文件」这件事反复失效

文档给的方案是 `adb push` 三样东西（`AssetBundle.dat`、`UnityCache/`、
`il2cpp/Metadata/global-metadata.dat`）。实测下来它**有概率失效**，
根因是客户端的状态机：

| 设备上的状态 | 客户端行为 |
|---|---|
| 没有 `files/AssetBundle.dat` | 会把 APK 内置的 155 个包读出来写进 `UnityCache`（179 MB），但自己只写一份 **226 字节空壳**清单（有版本号、没有清单字符串）→ 报**「过期资源」** |
| 有完整清单，但 `UnityCache` 是空的 | 认为「资源我都有了」，不去读 APK 里的包 → 真用到 `appdata` 时才失败，报**「无法连接…错误：appdata」** |
| 完整清单 **且** `UnityCache` 已铺好 | **正常进主菜单** |

所以「先推清单」还是「先铺缓存」顺序错了就必挂——这就是「有概率失效」的来源。

### 修法：把顺序做进 APK 自己

用 apktool 解包 → 在 `UnityPlayerActivity.onCreate` 里插一行

    invoke-static {p0}, Lcom/pmseed/SeedApplication;->seed(Landroid/content/Context;)V

`SeedApplication`（Java 编译成 `classes4.dex`）首次启动时：

1. `files/AssetBundle.dat` 不存在或比内置的小 → 从 `assets/AssetBundle.dat` 铺一份 31,826 字节的完整清单；
2. `files/UnityCache/Shared` 里包数 < 150 → 按 `assets/pmseed/index.txt`（构建时生成，每行 `<包名> <24个0+version小端hex>`）把 155 个包逐个铺进去，并写 `__info`。

只在「缺失」或「比内置小」时写，**绝不覆盖游戏自己写好的有效文件**。
这些动作在 `onCreate` 里同步完成，所以首启会慢约 1 分钟（约 179 MB I/O）。

**证据**：干净卸载后安装启动，未做任何 adb 操作，
`files/AssetBundle.dat` = 31,826 字节、`UnityCache` = 179 MB / 156 个目录。

## 3. 其它修复

| 位置 | 改动 | 原因 |
|---|---|---|
| `tools/build_enhanced.py` | 新增，替换掉一堆一次性手工命令 | 之前每个 APK 都是手搓的，所以才会互相回退 |
| 复验环节 | 每次构建后自动断言 7 项 | 上面 4 个 BUG 全是「静默」的，只有断言能拦住 |
| `run.py` `_warn_if_apk_target_stale()` | 支持多目标列表 | 同时存在 MuMu 版 / 通用版，单个标记会误报 |
| `pmnet/routes/cdn.py` | 新增 `GET /generate_204` → 204 空 body | Android 联网检测端点，它判「没网」客户端就一个请求都不发 |
| `run.py` 启动横幅 | 打印路由数与对外地址 | 排查时最常问的两件事 |
| `tools/patch_metadata_exact.py` | 新增，带 `--selftest` 对拍 | 原来的等长替换要么留 `/` 垃圾，要么不改长度前缀 |

### 关于 `patch_metadata_exact.py` 的一个诚实说明

这个脚本能做到「原地等长替换」，但**没能逐字节重放出社区那份「验证过能用」的
metadata**——对拍时仍有 716 字节不同。差异集中在：

* 数据区字符串的 7-bit 长度前缀（这部分它对得上）；
* 一张索引表里的 length 字段（社区版改了，它没改）。

所以最终产物**没有用它**，而是直接用社区那份经过实测的 metadata 做等长
host 替换（`127.0.0.1:8080` → `10.0.2.2:8080/`，长度相同）。脚本留在仓库里
是作为「这条路走过、结论如此」的记录。这一点没在别处写清楚过。

## 4. 实测验证（MuMu Player，Android 12 / arm64-v8a）

```
干净卸载 → 安装 315,988,853 字节的 APK → 启动
  files/AssetBundle.dat        31,826 字节        ✅ 由 APK 自己铺出
  files/UnityCache/Shared/     156 个目录 / 179MB ✅ 由 APK 自己铺出
  「过期资源」弹窗                                 ✅ 消失
  Unity 日志越过 analytics API Initialized         ✅ 不再停在那
  界面                                             ✅ 主菜单（战役 / 多人游戏 / 登录）
```

### 一个绕不过去的依赖（必须说清）

客户端开机第一件事是**不带 UA 的 `GET /` 做可达性探测**，拿不到 200 就
永远转圈、一个请求都不发。这是客户端自身设计，APK 层绕不过去。

**所以服务端必须开着。** 探测以外，客户端的账号/存档也确实需要服务端。

## 5. 产物与复现

```
PocketMortys-加强版.apk   315,988,853 字节
  sha256 eec4b0fbc7bf8ab7fb7b9c1bbd0f32dade88d2e90773c357f6883ae71b51104f
```

复现：

```bash
python3 build_java_layer.py --base 官方.apk --work /tmp/pmbase \
    --manifest ../server/cdn/Aliases/rat/Android/manifest.json \
    --dat 完整AssetBundle.dat -o /tmp/base-java.apk
python3 build_enhanced.py --base /tmp/base-java.apk --variant full \
    --metadata-host 10.0.2.2 --out PocketMortys-加强版.apk
```

第二步会打印逐项复验结果，任何一项不通过就以非 0 退出。
